# mpmoi engine (Go) — bridgev2 local connector

The pure-Go engine that replaces the Synapse homeserver layer. It runs the real
mautrix bridges (`bridgev2`) but swaps `bridgev2/matrix` (the appservice→Synapse
connector) for a **custom `MatrixConnector`** that writes bridge events straight
into the mpmoi product DB — no homeserver, no matrix-worker, cross-compilable to
Windows and (later) `gomobile` for on-device mobile.

Full rationale + staged plan: [`docs/bridgev2-local-connector-plan.md`](../docs/bridgev2-local-connector-plan.md).

## Status: Stage 0 — PROVEN GREEN (2026-08-05)
A real WhatsApp message from the phone lands as a `public.messages` row through
this connector with **no Synapse running**. Now on **Stage 1: inbox parity**
(porting `apps/matrix-worker/src/lib/sync.ts` fidelity into the connector).

## Files
- `connector.go` — `LocalConnector` implements `bridgev2.MatrixConnector` (deterministic IDs, ghost intents, no-ops).
- `intent.go` — `localIntent` implements `bridgev2.MatrixAPI`: `SendMessage`→`messages`, `CreateRoom`→`conversations`, `SetDisplayName`→title, media→disk, `GetEvent`→read-back.
- `store.go` — the product-DB sink (lib/pq) + in-memory room↔chat / event maps.
- `main.go` — wires `bridgev2.NewBridge(..., LocalConnector, WhatsAppConnector, ...)` (bypassing `mxmain`) + headless QR login.
- `run.sh` — seeds the FK rows and runs against the desktop dev product DB.

## Building
Depends on the locally-vendored WhatsApp bridge under
`infra/matrix-native/src-whatsapp` (regenerated by the native-stack build
scripts; not committed to git — see `replace` in `go.mod`). With it present:
```bash
go build .        # from this dir
```

## Running the WhatsApp round-trip (dev)
1. Start just the product Postgres:
   ```bash
   MPMOI_DATA_DIR="$HOME/Library/Application Support/mpmoi-dev" \
     pnpm --dir apps/desktop stack:up postgres
   ```
   (Sign in once via the app so an `auth.users` + default space exist.)
2. `./run.sh` — seeds a `whatsapp` `connected_accounts` row, exports the IDs,
   runs the engine, prints a QR. Scan it (WhatsApp → Linked devices), send a
   message, and watch `public.messages`.

## Known Stage-1 work (from the Stage 0 round-trip)
- Direction / self-chat / LID: self-sent messages currently mark `incoming` and
  leave `sender` unset — port the `sync.ts` self/LID logic.
- Reactions are currently written as empty-body messages; route them to the
  reactions table instead.
- Media is written to `$MPMOI_MEDIA_DIR`; wire to the product storage/gateway.
- Room↔chat / event maps are in-memory (fine per-session; persist for Stage 1).
- Before shipping: swap CGO `mattn/go-sqlite3` for pure-Go `modernc.org/sqlite`
  (bridge-state DB) so Windows cross-compile + `gomobile` keep working.
