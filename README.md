# mpmoi engine

The **mpmoi engine** — a standalone Go process that connects to chat networks
(WhatsApp, Signal, Instagram, Messenger) on the user's own device and writes the
messages into a local database. It is the open-source part of
[mpmoi](https://mpmoi.app): the desktop app, its UI, and the cloud are a
separate, proprietary program that talks to this engine only over a local
database + local HTTP — there is no linking and no shared address space.

## Layout

```
engine/                          our Go engine (main package, module github.com/Mouglie/mpmoi-engine)
  main.go, connector.go, ...     the LocalConnector that writes bridge events into the product DB
  build.sh                       build the mac/arm64 binary  → engine/mpmoi-engine
  build-win.sh                   cross-build windows/amd64   → engine/mpmoi-engine.exe
infra/matrix-native/
  src-whatsapp/                  vendored mautrix-whatsapp bridge (AGPL-3.0)
  src-signal/                    vendored mautrix-signal bridge + Signal's libsignal (AGPL-3.0 / GPL-3.0)
  src-meta/                      vendored mautrix-meta bridge — Instagram + Messenger (AGPL-3.0)
```

The engine's `go.mod` wires the bridges in with `replace` directives pointing at
the sibling `infra/matrix-native/src-*` directories, so the layout above must be
preserved for the build to resolve them.

## Building

Native artifacts are **not** committed (they are regenerated by the build
scripts — see `.gitignore`). Build order:

1. **libsignal** (Rust → `libsignal_ffi.a`). Needs a Rust toolchain.
   ```bash
   cd infra/matrix-native/src-signal && ./build.sh        # mac/native
   ./build-win.sh                                          # + windows/amd64 GNU-ABI .a
   ```
2. **the engine** (Go, cgo — links the `.a` from step 1).
   ```bash
   cd engine && ./build.sh          # → engine/mpmoi-engine       (mac/arm64)
   ./build-win.sh                   # → engine/mpmoi-engine.exe   (windows/amd64)
   ```

Toolchain notes are in the header comments of each build script.
